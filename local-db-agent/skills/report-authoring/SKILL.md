# 分析报告编写

## 适用范围

本技能只规定“报告怎么写”，不提供业务口径。指标定义、表含义、状态码仍从 `knowledge/` 或业务技能读取；命中 WMS 等业务技能时，先 `read_skill` 读业务技能，再用本技能组织报告。

## 开始前确认

1. 报告类型：日报 / 周报 / 月报 / 专题分析 / 汇报材料 / 大屏。
2. 统计周期与数据截止时点，周期是否完整（例如“本周”是否为完整自然周）。
3. 对比基准：上期、同期、目标、预算，或仅描述现状。
4. 受众与粒度：管理层看结论，业务看明细；组织/仓库/品类范围。
5. 指标口径：分子分母、单位、成本口径、状态范围。含糊时先问，不要猜。

## 推荐结构（4~8 个 section）

1. **摘要**：2~4 条核心结论，先给结论再给数字。
2. **核心 KPI**：2~4 个指标，带本期值、对比值、变化率。
3. **主趋势**：1 张主图，展示周期内走势或目标完成情况。
4. **结构/排名**：按维度拆解，Top N + 占比。
5. **异常与原因**：只写有数据支持的异常，说明下钻结论。
6. **数据质量与缺口**：缺失、口径待确认、异常值说明。
7. **建议**：可执行、与结论对应，不写空话。

报告类型不同可裁剪，但“摘要 + KPI + 主趋势 + 缺口说明”建议保留。章节模板见 `references/report-sections.md`。

## 图表选型

- 时间趋势用折线图；类别对比用条形图；构成用堆叠条形或饼图（类别 ≤6）；
- 分布用直方图/箱线图/热力图；相关性用散点图；排名明细用表格；
- 同一报告图表类型保持 2~3 种，避免每节换一种；
- 双轴图仅用于量纲不同且强相关的两条序列，并在图例中写清单位。

详细对照见 `references/chart-selection.md`。

## 写作要求

- 每个数字都能追溯到 `run_sql` / `run_saved_query` 的结果，不编造、不估算。
- 写“是什么、为什么、怎么办”，不写“我先查询了……”这类过程旁白。
- 单位、小数位、百分比口径全篇统一；比率写清分母。
- 明细表最多 10 行，超出给汇总或 Top N。
- 结论避免绝对化；样本不足或口径未确认时明确写“待确认”。

## coverage 规则

报告必须逐项标注：

- `ok`：已取到数据，且写明来源；
- `missing`：字段或数据确实缺失，写清原因；
- `needs_review`：口径待确认，不输出数值，只写说明；
- `pending`：尚未查询，禁止出报告。

## 输出

- 报告轮统一调用 `render_html_report`；只有普通问答的轻量卡片才用 `render_report`，单图才用 `render_chart`。
- HTML/CSS/ECharts 源码只放在工具参数里，禁止输出到聊天正文。
- 报告生成后正文只回一句确认，不复述全文。
