# WMS 出库履约分析

## 适用范围

适用于订单分配、拣货、复核、发运、退货等出库环节。不同 WMS 的订单类型、拆单规则和时间字段差异很大，本技能只给流程和算法，不假设真实表名。

## 先做概念映射（必做）

| 概念 | 需要确认 |
|---|---|
| 订单 | 销售订单、出库单、波次、发运单，是否拆单/并单 |
| 时间 | 下单、承诺发运、实际发运、签收、拣货开始/完成 |
| 状态 | 待分配、缺货、拣货中、已复核、已发运、取消、退货 |
| 数量 | 订单量、分配量、拣货量、发运量、签收量 |
| 承运 | 承运商、运输方式、是否自提 |
| 异常 | 缺货、短拣、错拣、破损、延迟、拒收 |

如果已加载知识包，先 `search_knowledge("WMS 出库 映射")` 并按返回的 `path` 调 `read_knowledge`；没有知识包时直接 `get_table_schema(detail="profile")` 并向用户确认映射。映射缺失时标 `needs_review`。

## 口径确认清单

- 满足率按订单、行还是数量计算；
- 完全满足与部分满足如何区分；
- 承诺时间用承诺发运时间还是承诺送达时间；
- 拆单/并单后按原订单号还是出库单号统计；
- 部分发运、取消、退货是否进入分母；
- 拣货准确率按行、数量还是复核差异；
- 时区、作业日、跨天边界。

## 分析步骤

1. Profile 订单、出库单、拣货任务、发运表，确认状态和数量字段。
2. 出 KPI：订单满足率、缺货率、准时发运率、拣货准确率、履约周期。
3. 看趋势：按日/周看订单量与履约指标。
4. 看结构：按客户、仓库、订单类型、承运商拆解。
5. 下钻异常：缺货 SKU、延迟订单、拣货差异、取消/退货原因。
6. 按 `report-authoring` 出报告并标注 coverage。

## 指标与通用 SQL 模式

表名、状态码均为占位符，执行前替换。

- 订单满足率 = 完全满足订单数 / 有效订单数；
- 行满足率 = 满足行数 / 订单行数；
- 缺货率 = 缺货行数 / 订单行数，或缺货数量 / 需求数量；
- 准时发运率 = 实际发运时间 ≤ 承诺发运时间的订单数 / 已发运订单数；
- 拣货准确率 = 无差异拣货行数 / 拣货行数；
- 履约周期 = 实际发运时间 - 下单时间（或签收 - 下单）；
- 退货率 = 退货数量 / 发运数量。

准时发运示例：

```sql
SELECT
  WarehouseID,
  SUM(CASE WHEN ShippedAt <= PromisedAt THEN 1 ELSE 0 END) * 1.0
    / NULLIF(COUNT(*), 0) AS on_time_rate
FROM YOUR_SHIPMENT
WHERE ShippedAt >= @from AND ShippedAt < @to
  AND status_code NOT IN (YOUR_CANCELLED_STATUS)
GROUP BY WarehouseID
```

- SQL Server：`DATEDIFF(hour, order_time, ship_time)`；
- 金仓：`EXTRACT(EPOCH FROM (ship_time - order_time)) / 3600`。

## 常见坑

- 用订单创建时间算履约周期，忽略审核/分配耗时；
- 拆单后按出库单统计，满足率被高估；
- 部分发运的订单被算作完全满足；
- 承诺时间与要求送达时间混用；
- 取消、退货订单未从分母剔除；
- 缺货只统计订单数，不统计缺货数量；
- 拣货差异未区分数量差异和错货；
- 跨时区发运时间未统一。

## 输出

建议结构：订单量与满足率 KPI → 趋势 → 客户/仓库/承运商结构 → 缺货与延迟明细 → 数据质量 → 建议。写清满足率的分母和拆单处理方式；无法映射的字段标 `needs_review`。
