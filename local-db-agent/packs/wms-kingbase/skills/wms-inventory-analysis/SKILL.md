# WMS 库存分析

## 适用范围

适用于各类 WMS 的库存分析。不同厂家表结构、状态码、单据类型差异很大，本技能只给分析流程和指标算法，**不假设任何真实表名**。

## 先做概念映射（必做）

在写 SQL 前，先把下列概念映射到当前库：

| 概念 | 需要确认 |
|---|---|
| 库存对象 | SKU / 批次 / 序列号 / 货主 / 组织 |
| 库存位置 | 仓库 / 库区 / 库位，是否有容量字段 |
| 库存状态 | 可用 / 锁定 / 在途 / 质检 / 冻结 / 不良品 |
| 数据形态 | 快照表还是流水表；快照频率与时点 |
| 金额口径 | 成本价 / 售价 / 移动平均；是否含税 |
| 单据类型 | 收货 / 上架 / 移库 / 拣货 / 发运 / 盘点 / 调整 |

做法：

1. 如果已加载知识包，先 `search_knowledge("WMS 库存 映射")` 找客户映射，再用返回的 `path` 调 `read_knowledge`；
2. 没有知识包或没搜到映射时，直接 `get_table_schema(tables=[核心表], detail="profile")`，并向用户确认表/字段/状态；
3. 用 profile 验证字段、状态枚举和日期范围；
4. 映射缺失或冲突时，标 `needs_review` 并向用户确认，不要猜表名或状态码。

**禁止**：猜表名、猜状态码、把流水表当快照、把锁定/在途库存直接算作可用。

## 口径确认清单

- 分析时点：哪一天的快照，时区是什么；
- 范围：组织、仓库、货主、品类；
- 状态：是否只算可用，是否含锁定、在途、质检、冻结；
- 单位：件 / 箱 / 托，换算系数是否统一；
- 金额：成本口径、税率、币种；
- 库龄起点：入库时间、生产日期还是批次日期；
- 周转公式：出库量 / 平均库存，还是 COGS / 平均库存；
- 负库存：保留、置零还是单独列出。

## 分析步骤

1. Profile 1~2 张核心表，确认快照时点、状态枚举、组织维度。
2. 先出 KPI：库存量、库存金额、周转、呆滞、库位利用率。
3. 看趋势和结构：按时间、仓库、品类、库龄、ABC。
4. 对异常下钻：呆滞集中在哪些 SKU/库位，负库存在哪些仓。
5. 校验：总数对账、快照重复、单位一致、日期边界。
6. 按 `report-authoring` 组织报告并标注 coverage。

## 指标与通用 SQL 模式

以下表名和状态码均为占位符，执行前替换为映射结果。

库存量（快照时点）：

```sql
SELECT item_id, SUM(qty) AS qty
FROM YOUR_STOCK_SNAPSHOT
WHERE snapshot_date = @as_of
  AND status_code IN (YOUR_AVAILABLE_STATUS)
GROUP BY item_id
```

库存金额：`SUM(qty * unit_cost)`，成本字段需确认是移动平均还是标准成本。

库龄分桶：

- SQL Server：`DATEDIFF(day, inbound_date, @as_of)`
- 金仓：`@as_of::date - inbound_date::date`
- 分桶：0~30 / 31~60 / 61~90 / 91~180 / 180+ 天。

周转：

- 周转次数 = 期间出库量 / 平均库存；
- 周转天数 = 期间天数 / 周转次数；
- 平均库存优先用每日快照均值，没有快照时用 `(期初 + 期末) / 2`，并注明口径。

呆滞：最近 N 天无出库且库存大于 0；N 由用户确认，未确认时不要自定。

ABC：按出库量或出库金额降序累计，A 类累计 70%、B 类 70%~90%、C 类其余；明细规则见 `references/metrics.md`。

库位利用率：已占用库位 / 可用库位，确认“占用”是只要有库存还是按容量计算。

账实差异：系统库存与盘点数量按 SKU + 库位 + 批次对齐，差异率 = 差异数量绝对值 / 系统数量。

## 常见坑

- 同一 SKU 在快照表有多行（库位/批次/状态），直接 `COUNT(*)` 会重复计数；
- 多个快照日期混算，导致库存翻倍；
- 把锁定、质检、在途库存算进可用；
- 库存表 join 明细表后行数放大，再 SUM 金额翻倍；
- 单位不统一（件/箱/托）导致数量不可加；
- 负库存未处理，周转和库龄失真；
- 库龄起点用错（入库时间 vs 生产日期）；
- 周转分子分母期间不一致（如 30 天出库除以月均库存）。

## 输出

优先按库存报告结构：KPI → 趋势 → 库龄/ABC 结构 → 呆滞与异常 → 数据质量 → 建议。每个 KPI 标注 coverage；映射缺失的维度写 `needs_review`，不要给数值。详细指标定义见 `references/metrics.md`。
