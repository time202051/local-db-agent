# WMS 入库履约分析

## 适用范围

适用于收货、上架、越库等入库环节。不同 WMS 对单据、状态和时间字段的定义差异很大，本技能只给流程和算法，不假设真实表名。

## 先做概念映射（必做）

| 概念 | 需要确认 |
|---|---|
| 单据 | 收货通知/ASN、收货单、上架任务、入库单 |
| 时间 | 通知时间、预约时间、到货时间、收货完成、上架完成 |
| 状态 | 待收货、部分收货、已收货、已上架、取消、关闭 |
| 差异 | 数量差异、破损、错货、批次错误、单据不符 |
| 越库 | 是否直接发运，是否有独立标识 |
| 粒度 | 单据头 / 行 / 批次 / 托盘 |

如果已加载知识包，先 `search_knowledge("WMS 入库 映射")` 并按返回的 `path` 调 `read_knowledge`；没有知识包时直接 `get_table_schema(detail="profile")` 并向用户确认映射。映射缺失时标 `needs_review`，不要猜状态码。

## 口径确认清单

- 及时率基准：要求到货时间、预约时间还是通知时间；
- 完成时间：收货完成还是上架完成；
- 时限：小时还是自然日/工作日；
- 部分收货、分批上架如何处理；
- 取消单、关闭单是否进入分母；
- 差异按行还是按数量计算；
- 时间窗、时区、跨天边界。

## 分析步骤

1. Profile 收货单、上架任务表，确认状态和时间字段。
2. 出 KPI：收货及时率、上架及时率、收货差异率、入库周期。
3. 看趋势：按日/周看及时率与到货量。
4. 看结构：按供应商、仓库、单据类型拆解。
5. 下钻异常：延迟集中在哪些供应商/仓库，差异类型占比。
6. 按 `report-authoring` 出报告并标注 coverage。

## 指标与通用 SQL 模式

表名、状态码均为占位符，执行前替换。

- 收货及时率 = 及时完成收货行数 / 应收货行数；
- 上架及时率 = 及时完成上架行数 / 已收货行数；
- 收货差异率 = 有差异行数 / 收货行数；
- 收货差异数量率 = `ABS(SUM(diff_qty)) / SUM(received_qty)`；
- 入库周期（dock-to-stock）= 上架完成时间 - 到货时间，按小时或天；
- 越库比例 = 越库收货量 / 收货总量。

及时判定示例：

```sql
SELECT
  WarehouseID,
  SUM(CASE WHEN ReceivedAt <= RequiredAt THEN 1 ELSE 0 END) * 1.0
    / NULLIF(COUNT(*), 0) AS on_time_rate
FROM YOUR_RECEIPT_LINE
WHERE ReceivedAt >= @from AND ReceivedAt < @to
GROUP BY WarehouseID
```

- SQL Server：日期差用 `DATEDIFF(hour, start_time, end_time)`；
- 金仓：`EXTRACT(EPOCH FROM (end_time - start_time)) / 3600`。

## 常见坑

- 用单据创建时间代替到货时间，导致及时率虚高；
- 部分收货时按单据计数，而不是按行/数量；
- 一单多行、拆单收货未合并；
- 把未关闭、已取消单据算进分母；
- 跨天、跨周末的时间差按自然日算，未说明；
- 收货数量单位与库存单位不同；
- 上架任务重复生成导致重复计数；
- 差异只统计数量，漏掉破损、错货、批次错误。

## 输出

建议结构：收货量与及时率 KPI → 趋势 → 供应商/仓库结构 → 延迟与差异明细 → 数据质量 → 建议。每个指标写清时间口径和分母；无法映射的字段标 `needs_review`。
