# WMS 仓储作业效率分析

## 适用范围

适用于收货、上架、拣货、复核、发运等作业的效率分析。不同 WMS 的任务模型、工时来源和计量单位差异很大，本技能只给流程和算法，不假设真实表名。

## 先做概念映射（必做）

| 概念 | 需要确认 |
|---|---|
| 任务 | 作业任务、任务类型、任务状态，是否按行/托盘/箱 |
| 时间 | 任务创建、开始、完成时间，是否含等待 |
| 人员 | 员工、班组、外包/临时工、出勤人数 |
| 工时 | 打卡工时、任务工时、标准工时 |
| 数量 | 件、箱、托、行，单位换算 |
| 资源 | 库位容量、设备、月台、班次 |

如果已加载知识包，先 `search_knowledge("WMS 作业 映射")` 并按返回的 `path` 调 `read_knowledge`；没有知识包时直接 `get_table_schema(detail="profile")` 并向用户确认映射。映射缺失时标 `needs_review`。

## 口径确认清单

- 作业量按行、件、箱还是托；
- 人数是否含外包、临时工、管理人员；
- 工时是否含休息、加班、等待；
- 标准工时从哪来，是否分作业类型；
- 环节耗时从任务开始到完成，还是从创建到完成；
- 峰值按小时、班次还是日；
- 库位利用率是否按容量计算；
- 多仓汇总前单位是否统一。

## 分析步骤

1. Profile 任务表、人员/工时表、库位表，确认任务类型和单位。
2. 出 KPI：作业量、人均作业量、工时效率、环节耗时、库位利用率。
3. 看趋势：按日/小时看作业量与效率，识别峰值。
4. 看结构：按仓库、作业类型、班组拆解。
5. 下钻瓶颈：等待时间长、加班多、库位紧张的环节。
6. 按 `report-authoring` 出报告并标注 coverage。

## 指标与通用 SQL 模式

表名、状态码均为占位符，执行前替换。

- 作业量 = 按任务类型统计完成量，单位必须统一；
- 人均作业量 = 作业量 / 出勤人数（或人数 × 工时）；
- 工时效率 = 标准工时 / 实际工时，或作业量 / 实际工时；
- 环节耗时 = 完成时间 - 开始时间，按作业类型分组；
- 峰值 = 按小时/日统计的最大作业量，同时给出峰值占比；
- 库位利用率 = 占用库位 / 可用库位；
- 设备利用率 = 设备作业时长 / 可用时长；
- 加班占比 = 加班工时 / 总工时。

小时峰值示例：

```sql
SELECT
  DATE_TRUNC('hour', CompletedAt) AS hour_bucket,
  COUNT(*) AS task_count,
  SUM(qty) AS qty
FROM YOUR_TASK
WHERE CompletedAt >= @from AND CompletedAt < @to
  AND status_code = YOUR_COMPLETED_STATUS
GROUP BY DATE_TRUNC('hour', CompletedAt)
ORDER BY hour_bucket
```

- SQL Server 用 `FORMAT(CompletedAt, 'yyyy-MM-dd HH:00')` 或日期截断函数；
- 金仓用 `date_trunc('hour', completed_at)`。

## 常见坑

- 人数只算正式工，漏掉外包/临时工，人效虚高；
- 工时含休息或等待，效率被低估；
- 作业量单位混用（件/箱/托）直接相加；
- 任务重复生成或取消任务未剔除；
- 环节耗时从创建算起，包含排队时间却当成作业时间；
- 峰值只看最大值，不给峰值占比和持续时间；
- 库位利用率的分母包含不可用库位；
- 多仓汇总前未统一班次和时区。

## 输出

建议结构：作业量与效率 KPI → 趋势与峰值 → 作业类型/班组结构 → 瓶颈与加班 → 数据质量 → 建议。写清人数和工时口径；无法映射的字段标 `needs_review`。
